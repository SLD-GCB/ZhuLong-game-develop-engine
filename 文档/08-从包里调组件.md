# 从包里调组件

> **这一篇是给拿到发行包的人的。** 包里有什么组件、每一个怎么调、哪些该调、哪些只是`可达`而不该
> 碰 —— 都在这里。
>
> 讲**烛龙自己怎么构建**的是 [01-构建](01-构建.md)，讲**烛龙自己怎么打包**的是
> [07-打包与发布](07-打包与发布.md)，讲每一层的**职责**的是 [02](02-内核.md) /
> [03](03-引擎.md) / [04](04-宿主.md)。每一句声明的原文在 [`参考/`](参考/)。

---

## 一、先说清楚：只有两个入口

包里**物理上**给了全部 15 个库和 80 个 `zlong/` 头 —— 八个内核子系统、引擎、宿主，都能 `#include`
也能链上。这是有意的（发的是接口，不是实现），但**能调不等于该调**：

| 语言 | 入口 | 你怎么拿到它 |
|---|---|---|
| C++ | `zlong::system::System` + `zlong::system::Platform` | `#include "zlong/system/system.h"` |
| Python | `zlong.System` + `zlong.Platform` | `import zlong` |

一个游戏、一个宿主程序，**只用这一个入口**：实现 `Platform`（窗口、声卡、输入），把它交给
`System`，剩下的由机器驱动。宿主不组装机器、不跑循环 —— 这是整个项目贯通全部代码的那一条规矩
（[README 的形状图](README.md)）。

下面每一条都标了 **该调** 还是 **可达，别调**。别调的意思不是"技术上不行"，是"那是机器的内政，
`System` 已经在下面接好了，你自己再接一遍就是重写它"。

## 二、在包里说话要用的五个坐标

写一行 `#include` 或者一条链接命令，需要的是这五样。**按 F5 的时候你一样都不用写** ——
编辑器全部从 `项目清单.json` 读（[07](07-打包与发布.md) 第三节）。这一段是给"拿 `zig.exe` 直接编"
和"想知道编辑器到底干了什么"的人看的。

| | 包里是什么 | 你写什么 |
|---|---|---|
| **头文件目录** | `include/`（所有头**拍平**在这一层） | `-Iinclude`，然后 `#include "zlong/gpu/gpu.h"` |
| **库** | `运行环境/ziglib/zlong.dll`（**整个后端一个二进制**） | `-L运行环境/ziglib -lzlong` —— 就这一条 |
| **宏** | `项目清单.json` 的「定义」 | `-DNDEBUG -DZL_GPU_WITH_VULKAN=1` |
| **Vulkan** | `运行环境/vulkan/` | `-I运行环境/vulkan/include`；导入库**按路径给**：`运行环境/vulkan/lib/vulkan-1.lib` |
| **垫片** | `工具链/` | `-include工具链/mingw_compat.h -I工具链/include`（只 C++ 用，C 不用） |

**链接行就一条：`-L运行环境/ziglib -lzlong`。**

从前不是这样 —— 那时候 `ziglib/` 里摊着**十五个 `.a`**，每个都得配自己那一层的 `-L`，漏一个就报
`unable to find dynamic system library 'zlong_gpu'`（听起来像编译器的问题，其实是少了 `-L`）。

现在整个后端是**一个 `zlong.dll`**：内核八层 + 引擎 + 宿主音频 + 第三方（dynarmic / fmt / mcl /
Zydis / Zycore）全在里面，1434 条导出。所以 `编码器/cpp.py` 的 `link_arguments` 也只发一条。

> **跑的时候 `zlong.dll` 得在 exe 旁边。** Windows 的加载器最先搜 exe **自己那一层**，所以编辑器
> 编完会把它复制过去（`编码器/cpp.py` 的 `bring_beside`，输出面板里会写一行「[放在旁边]
> zlong.dll」）。手动编的话要自己做这一步，否则双击 exe 会说找不到 `zlong.dll`。

**`ZL_GPU_WITH_VULKAN` 必须原样带上。** 它是 `PUBLIC` 宏，`gpu.h` 和 `system.h` 拿它圈**成员**；
少了它，你这边编出来的 `System` 和库里那份**布局不一样**，症状是链接通过、第一次调用就崩
（[01](01-构建.md)、[07](07-打包与发布.md) 都记着这一条）。

| 引擎·场景文件 | `zlong/engine/scene_file.h` | 同上 | 该调（**只有 C++**） |
| 引擎·渲染器 | `zlong/engine/renderer.h` | 同上 | 可达，别调 —— `System` 拥有它 |
| 引擎·声音渲染器 | `zlong/engine/sound.h` | 同上 | 可达，别调 —— 同上 |
| 内核·RAM | `zlong/ram/ram.h` | `zlong_ram` | 可达，别调 |
| 内核·SSD | `zlong/ssd/block_device.h` | `zlong_ssd` | 可达，别调 |
| 内核·cpu | `zlong/cpu/cpu.h` | `zlong_cpu` | 可达，别调 |
| 内核·gpu | `zlong/gpu/gpu.h` | `zlong_gpu` | 可达，别调 |
| 内核·audio | `zlong/audio/mixer.h` | `zlong_audio` | 可达，别调 |
| 内核·mount | `zlong/mount/mount.h` | `zlong_mount` | 可达，别调 |
| 内核·service | `zlong/service/kernel.h` | `zlong_service` | 可达，别调 |
| 宿主·编辑器接口 | `editor_host.h` | 在 `zlong.dll` 里（它只剩声明了） | 该调（想让程序出现在面板里） |

所以"链不上"不会成为你的错误 —— 每一个都链得上，包括你根本用不到的 dynarmic。

## 四、入口：`System` 和 `Platform` —— **该调**

一个最小的宿主，C++ 和 Python 各一份，两边做的是同一件事。

```cpp
#include <cstdio>

#include "zlong/system/system.h"

class MyHost final : public zlong::system::Platform {
public:
    bool Pump() override { return true; }          // false = 该收工了
    void Present(const std::uint8_t* rgba, std::uint32_t pitch,
                 std::uint32_t width, std::uint32_t height) override { /* 一帧画好了，RGBA8 */ }
    void OnFrame(zlong::engine::Scene& scene, double seconds) override { /* 一帧的动画 */ }
    void OnMix(zlong::engine::Scene& scene, double seconds) override { /* 一块的声音 */ }
};

int main() {
    zlong::system::System::Config config;
    config.width = 1280; config.height = 720;
    config.dram_bytes  = 512ull * 1024 * 1024;
    config.arena_bytes =  64ull * 1024 * 1024;     // 画面越大，arena 越大
    config.vulkan = true;

    zlong::system::System machine(config);
    if (!machine.ok()) { std::printf("%s\n", machine.error().c_str()); return 1; }

    zlong::engine::Scene scene;                    // 见第五节
    MyHost host;
    machine.set_platform(&host);
    if (!machine.Load(scene)) { return 1; }
    machine.Run(-1);                               // -1 = 一直跑
}
```

```python
import zlong

class MyHost(zlong.Platform):
    def pump(self) -> bool:
        return True
    def present(self, rgba: bytes, pitch: int, width: int, height: int) -> None:
        ...
    def on_frame(self, scene: zlong.Scene, seconds: float) -> None:
        ...
    def on_mix(self, scene: zlong.Scene, seconds: float) -> None:
        ...

config = zlong.System.Config()
config.width, config.height = 1280, 720
config.dram_bytes  = 512 * 1024 * 1024
config.arena_bytes =  64 * 1024 * 1024
config.vulkan = True

machine = zlong.System(config)
if not machine.ok():
    print(machine.error()); raise SystemExit(1)

scene = zlong.Scene()                              # 见第五节
machine.set_platform(MyHost())
if not machine.load(scene):
    raise SystemExit(1)
machine.run(3)
print(machine.frames(), machine.draws(), machine.faults())
```

**四个回调一个都可以不写**（`Platform` 每个都有默认实现），headless 的跑法一个字都不用实现：
`machine.Run(300)` 直接跑。

### `Config` —— 机器多大、用什么后端

| 字段 | 默认 | 是什么 |
|---|---|---|
| `dram_bytes` | 64 MB | guest 内存。arena、翻译表、模块镜像都从这同一本账上出 |
| `width` / `height` | 640×480 | 画面 |
| `arena_bytes` | 16 MB | 内核给渲染器**预留**的那一块。装不下就 `Load` 返回 false，不踩过去 |
| `vulkan` | false | 用 Vulkan 后端，而不是软件那个 |
| `require_vulkan` | false | 宁可起不来也**不回落**到软件渲染。游戏要这个，软件那条是正确性兜底、不是拿来玩的。隐含 `vulkan` |
| `frame_interval_ms` | 16.0 | `Run` 的节流。0 = 全速 |
| `audio_block_frames` | 480 | 一次混多少帧再交给声卡 |

### `System` 上的东西

| | 干什么 |
|---|---|
| `ok()` / `error()` / `note()` | 起没起来、为什么没起来、有什么非致命的话要说 |
| `backend_name()` | `"vulkan"` 或 `"software"` |
| `set_platform(Platform*)` | 借一个宿主。**不持有**，宿主自己管生命周期 |
| `set_audio(audio::Sink*)` | 借一个声卡。它同时接进内核的服务和引擎 |
| `Load(scene)` | 一个场景一次：上传、布局、留着 |
| `scene()` | 那个场景。在 `OnFrame` 里改它，下一帧就照改完的画 |
| `Frame()` / `Run(frames)` | 一帧 / 若干帧。`Run(-1)` 是直到宿主收工 |
| `Mix(seconds)` / `FinishAudio()` | 声音按秒喂；告诉设备没有下一块了 |
| `frames()` / `draws()` / `faults()` | 跑了多少帧、出了多少 draw、GPU 报了多少错 |
| `syncpoint_signals()` | GPU 同步点的信号数 —— 对表用的 |
| `ram()` / `gpu()` / `kernel()` / `renderer()` / `sound()` / `audio()` / `platform()` | 下面那些层的引用。**该调的那半边用不到它们**；它们是给内核测试和扩展留的 |
| `fault_log()` | GPU 的错，一条条 |

**Python 上少了**：`ram()` / `gpu()` / `kernel()` / `renderer()` / `sound()` / `audio()` /
`platform()` / `Mix` / `FinishAudio` / `fault_log`。也就是说**从 Python 驱动不了声音** —— 声音在
C++ 那一侧，或者由 `System` 自己按帧走。这是有意的：绑定的面做窄，前端拿到的是 `System`。

## 五、引擎：一个场景由什么组成 —— **该调**

场景是**纯数据**。引擎不认识模拟器，它是对着一个 `Scene` 和一个后端干活的。

### `scene.h` —— 场景本身

```
Scene { camera, ambient, background, shadow_map_size,
        meshes[], textures[], materials[], lights[], nodes[], sounds[], emitters[] }
```

| 动作 | 怎么办 |
|---|---|
| 加网格 / 材质 / 贴图 / 光 | `add_mesh` / `add_material` / `add_texture` / `add_light` —— **返回下标** |
| 加一个节点 | `add_node(mesh, material, local, parent = kNoParent)`，也返回下标 |
| 纯变换组 | `mesh = kNoMesh` 的节点 |
| 改一个已经加进去的 | `set_node_local` / `set_node_material` / `set_material_tint`（光、贴图没有 setter） |
| 读回来 | `node_count` / `mesh_count` / `material_count` / `texture_count` / `light_count`、`node_mesh` / `node_material` / `node_parent` / `node_drawable` |

**三条必须记住的**（都是踩过的）：

1. **父节点必须出现在子节点前面** —— `AddNode` 记的是下标。
2. **Python 里不能用 `scene.meshes.append(...)`**。`std::vector` 过到 Python 是**一份拷贝**，
   append 进那个列表就被丢掉了，场景还是空的、而且什么都不说。所以有 `add_mesh` 那一组。
3. **C++ 里没有 `set_node_local`** —— 那边 `scene.nodes[i].local = ...` 直接改字段。这四个
   `set_*` 是给 Python 的，因为 `nodes` 那个容器根本过不去。

### `mesh.h` / `math.h` —— 图元和变换

| | 出来的是什么 |
|---|---|
| `MakeBox()` | 单位立方体 `[-0.5, 0.5]³` |
| `MakeGrid(divisions, uv_tiles)` | 单位方片，XZ 平面，法线朝 +Y。`uv_tiles` 是烘进去的 |
| `MakeCylinder(sides)` / `MakeCone(sides)` | 绕原点高一个单位、半径 0.5 |
| `MakeSphere(rings, segments)` / `MakeDisc(sides)` | 直径一个单位 |
| `MakeCheckerTexture(size, cells)` / `MakeRippleNormalTexture(size, cells)` | 两张程序化贴图。**没有图片加载器** |

**还有五个改模型的**：`BakeMesh` 上面那四个 —— `ExtrudeFace(描述, 面号, 距离, …)` 把一个面沿
它自己的法线挤出一层并补上侧壁，`Subdivide(描述, …)` 做一次 Catmull-Clark 细分（"盒子变球"那
一步），`CornerCut(描述, 要切的点, 一段边长, …)` 把点到的那些顶点各切掉一个角，`DeleteFace(描述,
面号, …)` 删掉一个面并留下一个洞（这是唯一一个让面**变少**的，所以它会把没人指着的点一起丢掉、
重排剩下的）。它们和 `BakeMesh` 一样是**描述进描述出**的纯函数：不碰选择、不碰撤销、不碰画面，
那些是工具的事。

**硬边（crease）是细分那一条路上的一件东西**：`MeshDescription::creases` 是一张**边的表**
（低号在前的两个下标），表里的边细分的时候**不跟着变圆**。它是单独一张表而不是挂在面上，因为
一条边在焊接的描述里是**两个面共用出来的**，不是谁写下来的 —— 要记下来的那件事只是"这条边是硬
的"。文件里一行 `crease <低> <高>` 写一条，所以 `.model` 现在写 `mesh 4`；**`mesh 3` 的老文件照样
读得进来**（它只是没有硬边）。

存读在 `zlong/engine/model_file.h`：`WriteModel` / `ParseModel` / `LoadModel` / `SaveModel`，
格式见 [03-引擎](03-引擎.md) 的 model_file 一节。**路径是 UTF-8**，而且中文路径**不能走命令行**
（Windows 在进 `main` 之前就把它改了）—— 开文件走 `file_io.h` 那两个函数，别直接交给 `ifstream`。

读别人的网格文件在 `zlong/engine/obj_file.h`：`ParseObj` / `LoadObj`，读的是 **OBJ**，出来的就是
同一个 `MeshDescription` —— 所以"捏的"和"导的"在这一点上合成了一件事，见 [03-引擎](03-引擎.md)
的 obj_file 一节。

图元**都是单位大**，所以"放在地上"就是先缩放、再抬高它的一半。

变换：`Identity` / `Translation` / `RotationX` / `RotationY` / `RotationZ` / `Scale(1)` /
`Scale(x,y,z)` / `LookAt` / `Perspective` / `Orthographic` / `Radians`。

> **角度一律 `Radians(deg)`，不要手写小数。** 头文件里写着为什么：50 度写成 `0.8727` 会让投影偏
> `4e-5`，然后在近乎共面的边上把深度测试翻过来 —— 那不是读那个常量的人能猜到的。

**Python 这边的 `Mat4` 是不透明的**：只能由上面那几个函数造出来，唯一会做的运算就是 `*`。
而且 Python 只绑了 `rotation_y` **一个**旋转（C++ 三个都有）。

### `scene_file.h` —— 场景是文本（**只有 C++**）

```
background R G B [A]      ambient R G B      shadow SIZE
material R G B A [specular F] [texture I] [normal I]
node MESH MATERIAL PARENT X Y Z ROTY_DEGREES SCALE
```

一行一条指令，空白分隔，`#` 起注释。完整的语法表在 [03-引擎](03-引擎.md) 的 scene_file 一节。

`ParseScene(text, out, error)` / `LoadScene(path, out, error)`。现成的例子是
`宿主/scenes/demo.scene`（**不在包里**，那份文件开头自己就是格式说明书）。

**这两条 `import zlong` 拿不到。** 场景文件是给 C++ 程序读的。

### `renderer.h` / `sound.h` —— 别人在替你调

`Renderer::Prepare` / `Render` / `colour_pixels` 和 `SoundRenderer::Prepare` / `Mix` 都**不该由你
调**：`System::Load` 走的是 `Prepare`，`System::Frame` 走的是 `Render`，`System::Mix` 走的是
`Mix`。你从 `machine.renderer()` / `machine.sound()` 拿得到引用，但拿它去自己 Prepare 一遍，就是
和机器抢同一个 arena。

唯一值得读的是 `renderer().profile()` —— **每帧的时间都花在哪了**，毫秒。那是诊断，不是控制。

## 六、内核八层：可达，但那是机器的内政

八层各自负责什么，[02-内核](02-内核.md) 讲得很细。这里只说**从包里怎么看它们**。

| 层 | 头 | 库 | 一句话 |
|---|---|---|---|
| `ram` | `zlong/ram/ram.h` | `zlong_ram` | guest 物理内存 + 真的 MMU。所有分配从这同一本账上出 |
| `ssd` | `zlong/ssd/block_device.h` | `zlong_ssd` | 字节可寻址的块设备 + XCI/NSP 那类容器 |
| `cpu` | `zlong/cpu/cpu.h` | `zlong_cpu` | 四个 Cortex-A57，跑在四根宿主线程上（真并行） |
| `gpu` | `zlong/gpu/gpu.h` | `zlong_gpu` | Maxwell 3D，渲染进 guest 自己的显存。**没有窗口、没有交换链** |
| `audio` | `zlong/audio/mixer.h` | `zlong_audio` | 把声部求和成帧；重采样在这里 |
| `mount` | `zlong/mount/mount.h` | `zlong_mount` | 挂载表：名字 → 只读树 |
| `service` | `zlong/service/kernel.h` | `zlong_service` | 内核/HLE：`OnSvc` 是正门，各服务在这下面 |
| `system` | `zlong/system/system.h` | `zlong_system` | **就是第四节那个入口**，它拥有上面全部 |

**它们真的可达 —— 这不是空话。** 实测过一个不经过 `System` 的程序：

```cpp
#include "zlong/ram/ram.h"
int main() { zlong::ram::Ram ram(16ull * 1024 * 1024); return 0; }
```

编得过、链得上、跑起来退出码 0。同样地，包里 80 个 `zlong/` 头 + `editor_host.h` 一起放进一个
翻译单元，一次编过，退出码 0 —— 拍平到一个 `include/` 之后没有撞名。

**但"自己拼一套"就是重写 `System`。** 那些层要的内存、地址空间、后端、内核对象之间的接线
（谁交给谁、谁在什么时候被驱动）全在 `System` 的构造函数里，而 [参考/内核-system.md](参考/内核-system.md)
开头那段话就是在说这件事：*"每个宿主程序自己拼一份物理内存和 GPU……这是结束那件事的对象。"*
真想动它们，那是**扩展内核**，不是用引擎 —— 从源码树来，见 [02](02-内核.md)。

## 七、宿主那一面

| | 是什么 | 在哪 |
|---|---|---|
| `editor_host.h` | 让一个程序**在编辑器的右边面板里显示、并从那里收键盘**。295 行，**现在只剩声明**（实现被切进 `zlong.dll` 了），所以它也要 `-lzlong` | `include/editor_host.h` |
| `zlong_host_audio` | 声卡对 `audio::Sink` 的实现（WASAPI 共享模式）。因为它不止一个程序要用，才单独成库 | `运行环境/ziglib/宿主/` |
| `render_scene` / `viewer` / `mix_scene` / `xiangqi` / `gugong` | **五个宿主程序：不在包里** | 源码树 `宿主/` |

用编辑器当窗口，加两行就够（完整骨架见 [04-宿主](04-宿主.md)）：

```cpp
#include "editor_host.h"

if (zlong::editor::requested()) { editor_ = std::make_unique<zlong::editor::Host>(); }
// Pump() 里：editor_->Pump() 和 editor_->TakePresses()（虚拟键码，和窗口给的一样）
// Present() 里：editor_->Present(rgba, pitch, w, h)
```

编辑器会给它启动的**每个** C++ 程序设 `ZL_EDITOR_HOST=1`。不看这个变量的程序一切照旧 —— 同一个
程序既能独立跑，也能在编辑器里跑，不需要两份。

## 八、第三方：链上了，别直接调

| 库 | 是什么 | 为什么不该直接调 |
|---|---|---|
| `dynarmic` | ARM64 JIT | 内核的 `cpu` 层包着它。你的程序只跟 `cpu::Cpu` 说话 |
| `Zydis` / `Zycore` | x86 反汇编 | dynarmic 的依赖 |
| `fmt` | 格式化 | 同上 |
| `mcl` | 大数/有限域 | 同上，且它自己就是**钉住 Zig 0.13 的理由**（[01](01-构建.md)） |

它们出现在链接行上是因为 `项目清单.json` 的「库」表是平的，**不是**因为你有理由用它们。直接
`#include <dynarmic/...>` 当然编得过（头也在 `include/` 里），那就等于绕过内核去用它的一个零件。

## 九、Python 这一面少的那一半

Python 不是 C++ 的等价物，是一层**故意做窄**的绑定（`bindings.cpp` 开头自己写着
*"the surface here is narrow on purpose"*）。完整的表在
[`参考/Python-绑定.md`](参考/Python-绑定.md)，这里是"少了什么"：

| C++ 有 | Python 没有 |
|---|---|
| 整个内核：`Kernel` / `Ram` / `Gpu` / `MountTable` / `Cpu` / `Mixer` / `BlockDevice` | 全都没有 |
| `engine::Renderer` / `engine::SoundRenderer` | 没有 |
| `scene_file` 的 `ParseScene` / `LoadScene` | 没有 —— **Python 读不了 `.scene` 文件** |
| `math` 的 `RotationX` / `RotationZ` / `LookAt` / `Perspective` / `Orthographic` / `Dot` / `Cross` / `Normalize` / `Frustum` / `Bound` | 没有。Python 只绑了 `rotation_y`、`translation`、`scale`、`scale_xyz`、`identity`、`radians` |
| `Camera::View()` / `Projection(aspect)` | 没有。相机只给字段填，两个矩阵没绑 |
| `Texture` 的像素、`Mesh` 的顶点 | 只读数量（`vertex_count` / `index_count` / `width` / `height`）；**造贴图只有 `make_*_texture` 两条路** |
| `System::Mix` / `FinishAudio` / 下面各层的访问器 / `fault_log` | 没有 —— **Python 驱动不了声音** |
| `Platform*` 之外还借一个 `audio::Sink` | Python 只有 `set_platform` |

反过来说，Python 这边**有**的是完整的场景构造：`Scene` 的 `add_*` / `set_*` / `node_*` 一组、
六个 `make_*` 图元、两张 `make_*_texture`、六个变换函数、`kNoMesh` / `kNoTexture` / `kNoParent`。
**建一个场景、交给机器、画出来、把帧拿回来**，这条路 Python 是通的 —— 编辑器里那份「场景脚本」
模板走的就是它。

## 十、不经过编辑器，自己拿 `zig.exe` 编一个

按 F5 时编辑器做的一切，手敲就是下面这一条（实测过，退出码 0）：

```bat
运行环境\zig\zig.exe c++ -std=c++20 -O2 -w ^
  -include工具链\mingw_compat.h -I工具链\include ^
  我的游戏.cpp ^
  -Iinclude -I运行环境\vulkan\include ^
  -DNDEBUG -DZL_GPU_WITH_VULKAN=1 ^
  -o 我的游戏.exe ^
  -L运行环境\ziglib -lzlong ^
  运行环境\vulkan\lib\vulkan-1.lib ^
  -ladvapi32 -lcomdlg32 -lgdi32 -lkernel32 -lole32 -loleaut32 ^
  -lshell32 -luser32 -luuid -lwinspool
```

最后那一行十个是 CMake 默认链的 Win32 库，GNU 工具链自己知道它们在哪儿，报名字就够。

**更好的做法是让编辑器替你发这条命令**：在包里打开一个文件夹，写 `.cpp`，按 F5。它会从
`项目清单.json` 读头文件目录、宏、库和 Vulkan 的位置，然后按"**一个文件夹就是一个程序**"把旁边的
`.cpp` 一起编上（[05-编码器](05-编码器.md)、[07-打包与发布](07-打包与发布.md) 第四节）。

## 十一、包里没有的

写文档的人有责任说清楚哪里还没有，否则读的人会以为是自己的错。

| 没有 | 说明 |
|---|---|
| 内核 / 引擎 / 宿主的 `.cpp` | 发的是**接口**。实现全在 `运行环境/ziglib/zlong.dll` 里 —— **改不了内核，也读不到它**（我们自己的头过了刀：函数体挖掉，只剩类型和签名。唯一的例外是 2 处模板，C++ 规定它必须在头里） |
| 五个宿主程序 | `xiangqi`、`gugong`、`viewer`、`mix_scene`、`render_scene` 是"用机器写的程序"，不是机器。象棋和故宫特别说明了不带 |
| `宿主/scenes/demo.scene` | 上面那句的连带：那份示例场景跟着程序走，程序不在，它也不在 |
| 内容管道 | 没有图片、模型、音频加载器。图元、贴图、声音全是**程序化生成**的（`make_*` / `make_*_texture` / `MakeTone`） |
| 测试 | 两套都删掉了，见 [06-测试](06-测试.md) |
| CMakeLists / `.vcxproj` / `build/` | 包里一件构建树的东西都没有，见 [07](07-打包与发布.md) |

## 还有一条：整包一起用

把 `烛龙.exe` 从包里单独拷到桌面上，双击它，得到的是这个：

```
[用不了 C++] 没有编译器。找的是这一条：…\桌面\运行环境\zig\zig.exe
             编辑器算出来的包根是：…\桌面
```

编译器**只有一条路径**：`<包根>/运行环境/zig/zig.exe` —— 而包根就是"这个 exe 住在哪儿"。不给备胎、
不去 PATH 上找。所以一个被搬离了包目录的 exe 找不到编译器，而一个"会回退到这台机器碰巧装了什么"
的编辑器，是一个行为取决于机器的编辑器。（源码树里还有另一个同款症状 —— 文件树根和包根混起来，
见 [05-编码器](05-编码器.md) 的「两个根」一节。）
