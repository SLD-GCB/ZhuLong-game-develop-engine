# 测试

## 现状：**没有测试**

两套都从树里删掉了：

| 删掉的 | 原来是什么 |
|---|---|
| 十套 C++ 测试（`内核/*/tests/`、`引擎/tests/`、`宿主/xiangqi/tests/`） | ctest 那十套，各是一个独立可执行文件，入口 `tests/test_main.cpp` |
| `编码器/tests/`（十一个 Python 文件） | pytest 那套，约一百八十条，管编辑器这一半 |
| `编码器/examples/` | 样例脚本和一个用来量速度的旋转方块 |

所以现在：

- `ctest --test-dir build` **没得跑** —— 而且**连配置都过不去**，因为十个测试目标的
  `add_executable` 里还写着那些已经不在的 `tests/xxx.cpp`。配置时要显式关掉十个开关，见
  [01-构建](01-构建.md)。
- `pytest 编码器\tests` 会报 `file or directory not found`。

**这意味着验收只能靠人做。** [07-打包与发布](07-打包与发布.md) 里那份"从包里真的启动一次"的
清单就是这个意思 —— 它是**手工的**，没有自动化兜底。

这份文档留着，是因为下面两节还有用：**加测试的规矩**，和**那些被测试钉住的坑**。测试回来的时候
照着写，别让同样的坑再踩一遍。

## 加测试的规矩

- **C++ 侧跟着层走**：新测试文件加进那一层的 `tests/`，在那一层的 `CMakeLists.txt` 里
  `add_executable` + `target_link_libraries` + `add_test`，照抄隔壁那套。每套一个
  `tests/test_main.cpp` 当入口。
- **Python 侧跟着模块走**：一个模块一个文件。
- **别 mock 掉被测的东西**。编译就是真的编译，跑就是真的跑 —— 这条在打包那里也一样：**一个发行
  包只有真的从它里面启动过一次才算通过**。
- 测试用**隔离的 `QSettings`**（写进临时目录），界面测试跑在 `QT_QPA_PLATFORM=offscreen` 上，
  不弹窗、不动真实会话。

## 那些坑，要钉住

这张表不是"覆盖率"，是**踩过的**。每一条都曾经让某样东西**静默**地坏掉 —— 所以它们值得有测试
钉着，光写注释不够。

| 坑 | 症状 | 怎么钉 |
|---|---|---|
| `_fdopen(fd, "wb")` **不设二进制模式** | 帧里每个 `0x0A` 变成 `0x0D 0x0A`，尺寸相关、静默 | 用一个 **10 行**的帧当样本：8×8 的帧头不含 `0x0A`，看着是好的，恰好看不出问题 |
| 一帧一槽是**顶掉旧的**，不是排队 | 编辑器慢的时候画面"跳"，但不该让程序变慢 | 塞一串帧给一个很慢的通道，断言**最后进来的那个**真的显示了，而且**发送端不等** |
| `shlex.split` 会吃掉反斜杠 | `D:\a\b.png` 变成 `D:ab.png`，写到一个没人要的文件里 | `split_arguments` 用一个带 `D:\...` 的参数 |
| Windows 环境变量名**没有大小写** | 资源管理器给 `Path`，Unix 壳给 `PATH`；按原样存就查不到编译器 | 两种拼法都要能查到同一个值 |
| 合成按键事件**没有虚拟键码** | 面板**正确地**不发它 —— 容易被误当成"少发了" | 断言"没有原生键的事件被丢掉" |
| 一个程序**不止一个文件** | 只编 `main.cpp` 会缺 5 个源文件里的全部符号 | 真的编一个多文件程序并链接 |
| 没有窗口的程序不能被无限轮询 | 盯着一个永远不开窗口的进程会让编辑器空转 | 断言会放弃 |
| `hwnd = 0` 不是"没有窗口"，是"**整个屏幕**" | `PrintWindow` 会去抄整个屏幕 | 断言这种句柄被拒 |
| `cmake -E copy_if_different` 遇到不存在的目录 | 它**造出一个同名文件**，不报错 | 构建完查一下有没有多出个叫 `studio` 的文件 |
| 只把 `烛龙.exe` 拿出来用 | 它认的包根就是 `sys.executable` 那一层，编译器、内核、清单全找不到 | 断言"报错说清了它找的是哪条完整路径" |
| 一次失败的查找被记死 | 包重打好了，那个窗口还一直说"没有编译器" | 断言"没找到的下一次会重新找" |
| 编译器和文件树根混成一个 | 打开一个子文件夹看一眼源码，编译器就"消失" | 断言"换文件树根不影响编译器找到没有" |
| 打包器自己又写了一遍"哪些文件是一个程序" | `宿主/xiangqi/` 有六个 `.cpp`，但项目说这个程序是**五个源文件 + 一个库**（`rules.cpp` 属于那个库）。照着文件夹扫六个，就撞出 26 个 `duplicate symbol` | 断言"打包编的东西和按 F5 编的是同一套" |
| 产物目录落在游戏文件夹里面 | 打包第一步是清空输出目录 —— 游戏自己就没了（写测试时真撞上：脚本当场不见） | 断言这种计划被**拒绝**，而不是照做 |
| 打包器按"你打开的是哪个文件"定语言 | 它曾经还认 Python：在一个 C++ 游戏里点开一个 `.py` 看一眼，整个游戏就按 Python 打了；更荒唐的一次是拿 `编码器/` 自己（正好十三个 `.py`）当成一个 Python 游戏去冻结 | 断言"打包只有 C++ 一条路"（那条 Python 路已经删掉），以及"工作室自己的零件被拒绝" |

## 渲染回归

`宿主/render_scene` 会写 BMP（`--out`）。改了渲染路径之后，跟上一版的输出**逐字节比** ——
不一样就一定有一处变了，没有"看起来差不多"。

> 注意：`截图/` 里那几张**早于**修 viewport bug 的基线是**错的**（那时候非正方形的画面被纵向
> 拉长了 1.6 倍）。拿它们比出来的"没变"不算数。

**哪个编译器编的也有区别**：同一份源码，MSVC 和 Zig 编出来的画面在软件渲染那条路上会差**几个
像素**（浮点舍入）；Vulkan 那条路逐字节相同。所以基线要连着"是谁编的"一起记。
