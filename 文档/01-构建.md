# 构建

## 要装什么

| | 版本 | 干什么用 | 没有它会怎样 |
|---|---|---|---|
| CMake | ≥ 3.20 | 生成工程 | 什么都做不了 |
| Python 3.13 | 64 位 | 编辑器、Python 绑定 | 编辑器开不了；C++ 部分照常 |
| PySide6 | 6.x | 编辑器的界面 | 编辑器开不了 |
| Vulkan SDK | 1.4.x | `内核/gpu` 的 Vulkan 后端 | 只剩软件渲染，慢约 10 倍 |
| **一个 C++ 编译器** | 见下 | 编一切 C++ | 什么都做不了 |

`dynarmic` 和 `boost` **不用装** —— 它们躺在 `external/` 里。

**不要用 vcpkg**：它在这台机器上会卡死。要装库就下源码放进 `external/`。

---

## 两个编译器，各有各的用

这个项目里有**两套 C++ 工具链**，它们不是"新旧"，是分工。

### 一、Zig —— 出包用的那套，也是开发机上最省事的那套

`运行环境/zig/zig.exe`。一个二进制里就是 clang 前端 + lld 链接器 + mingw-w64 的头和库 +
libc++，整套齐。**版本钉在 0.13**（clang 18）：0.16 的 clang 21 收紧了模板模板参数的匹配规则，
`dynarmic` 自带的 `mcl` 编不过 —— 试过，不是猜的。

它同时扮演两个角色：

- **编辑器编 C++ 用的就是它**（`编码器/cpp.py` 里的 `Toolchain`，只认这一条路径，没有备胎）
- **打包时整个项目由它重编一遍**，产物进 `运行环境/ziglib/`

**你不需要手敲 Zig 的 CMake 命令** —— `打包.py` 把它整套做完了（配 `ZL_ZIG` / `ZL_COMPAT`
两个环境变量、写四个 `.cmd` 包装器给 CMake 当 CC/CXX/AR/RANLIB、用 Ninja 配置、构建、收 `.a`）。
要出包就直接：

```bat
python 打包.py
```

### 二、Visual Studio —— 为了 `build/` 那份构建树

如果你只想**开发**（改内核、引擎、宿主，跑一跑看），Visual Studio 这条路照样通：

```bat
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DZL_BUILD_PYTHON_BINDINGS=ON ^
  -DZL_BUILD_CPU_TESTS=OFF -DZL_BUILD_RAM_TESTS=OFF -DZL_BUILD_SSD_TESTS=OFF ^
  -DZL_BUILD_GPU_TESTS=OFF -DZL_BUILD_AUDIO_TESTS=OFF -DZL_BUILD_MOUNT_TESTS=OFF ^
  -DZL_BUILD_SERVICE_TESTS=OFF -DZL_BUILD_SYSTEM_TESTS=OFF -DZL_BUILD_ENGINE_TESTS=OFF ^
  -DZL_BUILD_XIANGQI_TESTS=OFF
cmake --build build --config Release
```

**那一长串 `=OFF` 不能省。** 十个测试目标的 `add_executable` 里写死了 `tests/xxx.cpp`，而那些
源文件**已经从树里删掉了**；开关默认是 `ON`，于是 CMake 在**配置阶段**就报

```
CMake Error at 内核/cpu/CMakeLists.txt:22 (add_executable):
  No SOURCES given to target: zlong_cpu_tests
```

十个全中，一个目标都建不出来。把开关关掉是**必须**的，不是"少编点东西的优化"。

### 生成器必须是 Visual Studio 吗

以前是，现在不是 —— 但**开发时仍然建议用它**：

- 编辑器从源码跑的时候，读 `build/**/*.vcxproj` 来知道"每个程序由哪些源文件组成、该链哪些库"。
  别的生成器不写这些文件。
- 出包时不靠它：包里没有源码，编辑器读的是 `项目清单.json`。

`-A x64` 不能省。库和 `dynarmic` 都是 x64。

## 开关

| 变量 | 默认 | 说明 |
|---|---|---|
| `ZL_BUILD_PYTHON_BINDINGS` | `OFF` | 生成 `zlong` 这个 Python 模块，**编辑器要它**。需要 Python + pybind11 |
| `ZL_GPU_WITH_VULKAN` | `ON` | Vulkan 后端。关掉就只剩软件渲染 |
| `ZL_BUILD_{CPU,RAM,SSD,GPU,AUDIO,MOUNT,SERVICE,SYSTEM,ENGINE,XIANGQI}_TESTS` | `ON` | 十个测试目标。**源文件已经删了，必须显式关掉**，见上面那串 `=OFF` |

`ZL_GPU_WITH_VULKAN` 被声明为 **`PUBLIC`**，因为它会改变头文件里的类布局（`gpu.h` 和 `system.h`
用 `#if defined(ZL_GPU_WITH_VULKAN)` 圈成员）。任何自己编一个用到 `zlong::system` 的程序**都必须
带上这同一个宏**，否则布局不一致，**链接通过、第一次调用就崩**。编辑器的宏来自项目清单
（包里）或 `CMakeCache.txt`（源码树），所以不会猜错。

**改了开关就要整棵重编**（包括那些静态库），不然新旧两种布局会混在一起。

## 产物落在哪

**Visual Studio 这条**（`build/`）：

```
build/内核/<层>/Release/zlong_<层>.lib     ← 内核各层的静态库
build/引擎/Release/zlong_engine.lib
build/宿主/Release/*.lib                   ← 宿主自己的库
build/宿主/zlong_<程序>.exe                 ← 宿主程序
build/内核/system/Release/zlong.cp313-win_amd64.pyd   ← Python 模块
build/**/*.vcxproj                         ← 编辑器（源码模式）靠它认识每个程序
```

**Zig 这条**（`build-zig/`，由 `打包.py` 驱动）：`.a` 而不是 `.lib`，可执行文件在
`build-zig/宿主/`。`build-zig/` 是中间产物，**打包时只从里面捡 `.a`**。

`build/` 现在主要剩下一个用途：**`打包.py` 从它读 Vulkan 的路径和"库都叫什么名字"**（从
`.vcxproj` 和 `Release/*.lib` 里）。用户那边一点不碰。见
[07-打包与发布](07-打包与发布.md) 的"有意留下的空缺"。

## Python 绑定

`内核/system/python/bindings.cpp` 把 `System` 绑成模块 `zlong`。它**不是**一个协议层 —— 就是把
那个类给出去，因为前端是 Qt/Python、后端是 C++，中间最省事的桥就是绑定本身。

开关一开，CMake 会：

1. 问解释器要 `pybind11` 的头文件目录（`python -c "import pybind11; print(pybind11.get_include())"`），
   所以 pybind11 **必须装在这个解释器里**：`python -m pip install pybind11`；
2. 编出 `zlong.cp313-win_amd64.pyd`。

**模块放哪儿是打包脚本的事，不是这个 CMakeLists 的事**：`打包.py` 把它放进自带解释器的
`site-packages/`，于是 `import zlong` 什么都不用设。

> 这里以前有一句 `POST_BUILD`，把模块拷到 `宿主/studio/`（"工作室旁边"）。工作室早搬到
> `编码器/` 了，那个目录不存在，于是 `cmake -E copy_if_different` 把它拷成了**一个叫 `studio`
> 的文件**，还会跟着包走。删掉了。

**用哪个编译器编的这份 `.pyd`，是有区别的**：

| | 导入表里有 | 后果 |
|---|---|---|
| MSVC 编的 | `MSVCP140.dll`、`VCRUNTIME140.dll` | 这两个 DLL 得让加载器找得到 |
| **Zig 编的**（包里那份） | 只有 `python313.dll`、`KERNEL32.dll`、`vulkan-1.dll`、UCRT | libc++ 和 C++ 运行库**静态链进去**，自足 |

所以出包时 `打包.py` 会带上 `-DZL_BUILD_PYTHON_BINDINGS=ON` 让 Zig 编一份，并把
`Python3_EXECUTABLE` 钉死成"正在跑打包的那个解释器" —— 包里的 Python 运行环境就是从它身上拷
的，ABI 标签（`cp313`）必须和它对得上。

编辑器**不需要**你设 `PYTHONPATH`：`编码器/runtime.py` 自己会找（先 `运行环境/`，再
`build/**/`）。

## 常见错误

| 现象 | 原因 |
|---|---|
| `No SOURCES given to target: zlong_*_tests` | 十个测试开关没关掉，而测试源文件已经删了。见上面那串 `=OFF` |
| `fatal error C1083: 无法打开包括文件: "dynarmic/interface/A64/a64.h"` | 少了 `external/dynarmic/src` 在 include 路径上 |
| 链接通过、一运行就崩（`0xC0000409`） | 少了 `ZL_GPU_WITH_VULKAN=1`，类布局对不上 |
| `cannot open input file 'vulkan-1.lib'` | 没装 Vulkan SDK，或者头文件和 `.lib` 不是同一版 |
| 编辑器里按 F5 编 C++ 说"没有编译器" | 那行消息会把**它找的那条完整路径**和"它认的包根"打出来，照那个查：整个包目录要一起用，不要只把 `烛龙.exe` 拿出来 |
| CMake 报 `cmake_minimum_required` 太老 | `dynarmic` 自带的老 CMakeLists；项目根已经设了 `CMAKE_POLICY_VERSION_MINIMUM 3.5` 兜底 |
| Zig 0.16 编 `mcl` 报模板参数不匹配 | 换回 0.13。这是**版本要求**，不是配置问题 |
| 第一次用 Zig 链接，吐一片 `_Unwind_*` / `unw_*` 的 `dllexport` 警告 | 那是 Zig 在编它自己的 libunwind 运行库，不是你的代码。进缓存之后不再出声。`-w` 管不到它内部的编译 |
