# 烛龙 开发者文档

**烛龙**是一台 Switch 模拟器，同时它的 GPU 层和引擎层本身就是一个游戏开发工具。这台机器向下
模拟一台游戏机，向上提供一个能写游戏的引擎和编辑器 —— 同一套代码，两个身份。

这份文档是**用法**：每一层是什么、怎么用、哪儿有坑。每一条公开声明的**签名**在
[`参考/`](参考/) 里，那是从源码里抄出来的，不会跟代码走散。

---

## 五分钟

**只想用，不想构建**：拿 `发行/烛龙-<日期>.zip`，解压，**双击 `烛龙.exe`**。

包里自带 Python、PySide6，和**一个 C++ 编译器** —— 什么都不用装。**没有启动脚本**，那个 exe
就是全部。见 [07-打包与发布](07-打包与发布.md)。

**要从源码构建**：

```bat
:: 1. 配置（那一串 =OFF 不能省：测试源文件已经删掉了，开关还开着，配置就过不去）
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DZL_BUILD_PYTHON_BINDINGS=ON ^
  -DZL_BUILD_CPU_TESTS=OFF -DZL_BUILD_RAM_TESTS=OFF -DZL_BUILD_SSD_TESTS=OFF ^
  -DZL_BUILD_GPU_TESTS=OFF -DZL_BUILD_AUDIO_TESTS=OFF -DZL_BUILD_MOUNT_TESTS=OFF ^
  -DZL_BUILD_SERVICE_TESTS=OFF -DZL_BUILD_SYSTEM_TESTS=OFF -DZL_BUILD_ENGINE_TESTS=OFF ^
  -DZL_BUILD_XIANGQI_TESTS=OFF
cmake --build build --config Release

:: 2. 开编辑器
python 编码器\main.py

:: 3. 出包（这一步会用包里的 Zig 把整个项目重编一遍）
python 打包.py
```

在编辑器里按 F5 就跑当前文件：`.py` 用解释器跑（能 `import zlong`），`.cpp` 编出来再跑，画面出现
在右边的面板里。

**写完一个游戏想拿给人玩**：工具栏上那个「打包游戏」，它把当前文件所在的**文件夹**打成一个
`<游戏名>.exe` 加一个 `依赖库/`。见 [05-编码器](05-编码器.md)。

**一个程序不止一个文件。** 一个不属于任何已知目标的文件，按**文件夹**算一个程序 —— 它旁边的
`.cpp` 一起编。`宿主/xiangqi/main.cpp` 旁边有五个，所以它编得动。

> **源码树里第一次编 C++ 之前，先跑一次 `python 打包.py`** —— 编辑器要链的是内核的 `.a`，
> 而它们是那一步产出的。没有它们，编辑器会明确地告诉你这件事。

想直接看象棋（源码树里有）：打开 `宿主/xiangqi/main.cpp`，按 F5。

## 这台机器的形状

```
                     ┌──────────────────────────────────────────┐
                     │  内核/system  System —— 那台"机器"        │
                     │  拥有下面的一切，并且驱动整个循环          │
                     └───────────────┬──────────────────────────┘
                                     │
              ┌──────────────────────┴──────────────────────┐
              │                                             │
    ┌─────────▼─────────┐                        ┌──────────▼─────────┐
    │ 内核/  （内核那一半）│                        │ 引擎/ （引擎那一半） │
    ├───────────────────┤                        ├────────────────────┤
    │ RAM  内存 + MMU    │                        │ math   线性代数     │
    │ SSD  块设备        │                        │ mesh   程序化网格   │
    │ cpu  四核 A57      │                        │ scene  场景即数据   │
    │ gpu  Maxwell 3D    │                        │ renderer 画出 draws │
    │ audio 混音         │                        │ sound  声部         │
    │ mount 挂载表       │                        │ scene_file 场景文本 │
    │ service 内核/HLE   │                        └────────────────────┘
    └───────────────────┘
                                     │
              ┌──────────────────────┴──────────────────────┐
              │                                             │
    ┌─────────▼──────────┐                       ┌──────────▼──────────┐
    │ 宿主/  （用机器的程序）│                       │ 编码器/ （写程序的工具）│
    ├────────────────────┤                       ├─────────────────────┤
    │ render_scene        │                       │ 编辑器：树/标签/运行   │
    │ gugong    故宫       │                       │ 画面面板 + 键盘       │
    │ viewer    窗口       │                       │ frames.py 帧线        │
    │ mix_scene 声音到文件  │                       │ cpp.py   编 C++（Zig）│
    │ xiangqi   象棋       │                       │ editor_host.h 让 C++ │
    │ audio_device 声卡    │                       │   在面板里当窗口      │
    └────────────────────┘                       └─────────────────────┘
```

**一条规矩贯穿全部**：宿主不组装机器、不跑循环。宿主实现 `Platform`（窗口、声卡、输入），
把它交给 `System`，剩下的由机器驱动。`内核/system` 是顶层，它拥有 `内核/` 和 `引擎/` 两边并驱动
它们 —— 所以一个宿主程序**只用** `zlong::system`，不用它下面任何一层。

**发行包里只有左边这一竖**：编辑器、**一个 `zlong.dll`**（`内核 + 引擎 + 宿主音频` 全部收进去
的那一个二进制）、接口的头、两套解释器。宿主是「用内核写的程序」，**不进包**。

**包里没有一个 `.cpp`**，产品目录里也没有 `.py`（运行环境里是字节码）。我们自己的头**过了一遍
刀**：只留类型、签名和常量，实现全在 `zlong.dll` 里。唯一绕不开的是 **2 处模板** —— C++ 规定
模板的定义必须在头里。见 [07-打包与发布](07-打包与发布.md) 的「C++ 那一半」一节。

## 两条走法

**当模拟器用**：`内核/service` 是 guest 的门。`Kernel::OnSvc` 收系统调用、`OnInterrupt` 收异常、
`BootConfig` 描述启动镜像，`mount::MountTable` 把 guest 的路径翻译成宿主上的只读树，`fsp` 服务
在上面跑。guest 的画面由 `gpu` 渲染进 guest 自己的显存 —— GPU 层**没有窗口、没有交换链**，
显示是后面的事。

**当游戏引擎用**：一个 `Scene` 是纯数据。`Renderer::Prepare` 一次上传，之后每帧只改
per-drawable 的常量。`SoundRenderer` 走同一批节点，把 emitter 变成声部，交给 `audio::Mixer`。
你写的是一个宿主：实现 `Platform`，把场景交给 `System`，然后按 F5。

两条路不冲突 —— 引擎的着色器本身就是 Maxwell 机器字，走的是和 guest 一样的解码路径。

## 约定

| | |
|---|---|
| 命名空间 | `zlong::<层>`，例如 `zlong::ram`、`zlong::engine`。对外只暴露头文件 |
| 头文件 | `内核/<层>/include/zlong/<层>/*.h`，`引擎/include/zlong/engine/*.h`。**发包时全部拍平到一个 `include/`**，而且**我们自己的那些会切掉实现**（只留类型和签名） |
| 命名 | 目录顶层用中文、内部全 ASCII 小写；文件 `snake_case`；类型和函数 `PascalCase`；成员 `snake_case_`（尾下划线）；常量 `kPascalCase`。见 [09](09-游戏开发范式.md) |
| 图标 | 源图是项目根目录的 `烛龙.jpg`，`打包.py` 把它生成 `.ico`（7 个尺寸），两个 exe 各自嵌进去。见 [07](07-打包与发布.md) |
| 语言 | C++20。**两个编译器**：Zig（`运行环境/zig`，随包发、也是编辑器编 C++ 用的那个）/ MSVC（开发时为了得到 `build/`） |
| 源码编码 | **UTF-8**。注释和字符串里都有中文 |
| 依赖 | 只有两份第三方：`dynarmic`（ARM64 JIT）和 `boost`（dynarmic 的头文件依赖）；Vulkan SDK |

**不要用 vcpkg**：它在这台机器上会卡住。

写文档的人有责任说清楚哪里还没做完，否则读的人会以为是自己的错。

| 空缺 | 在哪 |

| **2 处模板函数的体留在头里** —— C++ 规定模板的定义必须在头里，这是「不露源码」唯一绕不开的一类 | [07](07-打包与发布.md) |
| 建模器**不能选边**（硬边是「一个面的整圈」一次标的）、**没有多选**、**不能展开 uv**、**没有骨架动画** | [10](10-3D建模器.md) |
| 配置必须显式关掉十个测试开关，否则 CMake 在配置阶段就停 | [01](01-构建.md) |
| **出包这台机器仍然要有一份 `build/`**（Visual Studio 生成的）：`打包.py` 从它读 Vulkan 的路径和库名 | [07](07-打包与发布.md) |
| 打包装不进一份**正在运行**的包（旧的那份占着文件），中途失败还会留下半个包 | [07](07-打包与发布.md) |
| 语言下拉框说"这是 C++"**已经不管用了**：`.txt` 当 C++ 编不进去（MSVC 时代的 `/Tp` 没接过来） | [05](05-编码器.md) |
| guest 异常入口没实现，中断到不了 guest —— 这个缺口是被**计数**的，不是被藏起来的 | `内核/service` |
| 阴影贴图在屋顶上有一道黑楔子，抬高 bias 无效，两个故宫视角都关掉了阴影图 | `引擎` + `宿主/gugong` |
| 引擎读回帧缓冲是瓶颈：1024×640 只有 42fps，面板再快也没用 | [05](05-编码器.md) 的性能一节 |
| 定到 60fps 实际落在 56fps —— Windows 的 `sleep_for` 粒度约 15.6ms，不是面板的锅 | 同上 |
| 画面帧是**最新一帧胜**，不是全部保留：编辑器跟不上时旧帧被丢掉，只记数不排队 | 同上 |
| 第一次用 Zig 链接会吐一片 `_Unwind_*` 的 `dllexport` 警告 | [01](01-构建.md) |
